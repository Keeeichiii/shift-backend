1. ОБЩЕЕ ОПИСАНИЕ
--------------------------------------------------------------------------------

FredAvto — инновационная веб-платформа краткосрочной и долгосрочной аренды
автомобилей (каршеринг). Проект объединяет публичный сайт для клиентов,
личный кабинет, модерацию документов, каталог автомобилей, карту зон,
долгое бронирование, новости, поддержку и административные панели в одном
приложении.

Слоган на главной странице: «Каршеринг: новый уровень мобильности».

Целевая география: Республика Беларусь, в первую очередь Гродно и регион.
Валюта и тарифы: белорусский рубль (BYN). Контакты и формат телефонов
ориентированы на +375.


2. ИЗ ЧЕГО СОСТОИТ ПРОЕКТ
--------------------------------------------------------------------------------

2.1. Архитектура

  • Backend: Java 17, Spring Boot 4.0.5
  • Данные: Spring Data JPA, PostgreSQL + PostGIS (геоданные)
  • Миграции: Liquibase (37 change-файлов, полная схема БД)
  • Безопасность: Spring Security, сессионная аутентификация
  • Frontend: статические HTML/CSS/JS страницы, Leaflet для карт
  • Сборка и деплой: Maven, Docker (порт 8090), docker-compose для локального
    и образного запуска; возможность публикации на Railway и других PaaS

2.2. Структура приложения (логические модули)

  Публичный сайт
    — главная, услуги, карта, новости, советы, заправка, страница авто

  Аутентификация и профиль
    — регистрация, вход, выход, профиль пользователя, загрузка документов

  Каталог и fleet
    — карточки автомобилей (vehicle cards) с категориями и тарифами
    — сущности автопарка (vehicles) в БД и REST API

  Долгое бронирование
    — календарь, расчёт стоимости, заявки, модерация заявок

  Поездки (trips)
    — API для учёта поездок (UI создания поездки для пользователя — в разработке)

  Поддержка
    — обращения пользователей, просмотр модератором

  Администрирование
    — управление пользователями и ролями (ADMIN)
    — модерация прав, новости, карточки авто, заявки (MODERATOR)

  Инфраструктура
    — инициализация демо-данных, тесты, Docker, документация (SQL, use-case)

2.3. Роли пользователей

  Гость (неавторизованный)
    Просмотр публичных страниц, регистрация, вход.

  USER (клиент)
    Личный кабинет, документы, история поездок (просмотр), долгое бронирование,
    обращения в поддержку.

  MODERATOR
    Всё, что USER, плюс: модерация водительских прав и документов, заявки на
    долгую аренду, CRUD карточек автомобилей, новости, просмотр обращений
    в поддержку.

  ADMIN
    Всё, что MODERATOR, плюс: управление пользователями, назначение ролей,
    панель администратора.

  Наследование прав: USER ⊃ Guest, MODERATOR ⊃ USER, ADMIN ⊃ MODERATOR.


3. ПОЛНЫЙ ФУНКЦИОНАЛ ПО РАЗДЕЛАМ
--------------------------------------------------------------------------------

3.1. Главная страница (index.html)

  • Брендинг FredAvto, навигация по сайту
  • Hero-блок с призывом найти автомобиль
  • Блок тарифов: поминутная ставка (0,39–2,49 BYN/мин), пакеты на часы,
    долгое бронирование — с отсылкой к каталогу услуг
  • Карта подачи/зон на Leaflet (интерактивная)
  • Контакты, футер
  • Модальные окна входа и регистрации
  • Динамическое меню: для авторизованных — выход, ссылка на админ-панель
    (для ADMIN)

3.2. Услуги (services.html)

  • Каталог автомобилей по категориям:
      standard, comfort, business, electric, cargo, exclusive, long_booking
  • Карточки с фото, характеристиками, тарифами (минута, пакеты, долгая аренда)
  • Переход на детальную страницу автомобиля

3.3. Страница автомобиля (vehicle.html)

  • Детальное описание выбранной модели из каталога
  • Тарифы и параметры конкретного авто

3.4. Карта (map.html)

  • Интерактивная карта на Leaflet
  • Зоны завершения поездки / парковки (заданы в клиентском JS)
  • Ориентация на городскую мобильность

3.5. Личный кабинет (account.html)

  • Просмотр и редактирование профиля
  • Загрузка документов для верификации (водительское удостоверение и др.)
  • Статусы модерации документов
  • История поездок (чтение через API)
  • Раздел долгого бронирования: выбор авто, даты, расчёт цены, отправка заявки
  • Статусы заявок на долгую аренду

3.6. Поддержка (support.html)

  • Форма обращения для авторизованных пользователей
  • Тема и текст сообщения

3.7. Новости (news.html)

  • Лента новостей сервиса (публичный просмотр)
  • Контент управляется модератором

3.8. Советы (tips.html)

  • Статический информационный раздел для клиентов каршеринга

3.9. Заправка (fueling.html)

  • Правила и инструкции по заправке автомобилей каршеринга
  • Адаптация под белорусский контекст (локальные АЗС, порядок действий)

3.10. Панель модератора (moderator.html)

  • Модерация загруженных документов и прав (одобрение / отклонение)
  • Управление заявками на долгое бронирование
  • CRUD карточек автомобилей в каталоге
  • Управление новостями
  • Просмотр обращений в поддержку

3.11. Панель администратора (admin.html)

  • Список пользователей системы
  • Назначение и снятие ролей (USER, MODERATOR, ADMIN)
  • Блокировка / разблокировка учётных записей (при наличии в API)

3.12. REST API (backend)

  Основные группы эндпоинтов:
    • /api/auth — регистрация, вход, выход, текущий пользователь
    • /api/users, /api/admin/users — профиль и админ-управление
    • /api/documents — загрузка и статусы документов
    • /api/moderator/documents — модерация
    • /api/vehicle-cards — каталог для сайта
    • /api/moderator/vehicle-cards — редактирование каталога
    • /api/vehicles — автопарк (API; UI админки fleet — ограничен)
    • /api/trips — поездки
    • /api/long-booking — долгое бронирование (календарь, цена, заявки)
    • /api/moderator/long-booking — модерация заявок
    • /api/news — новости
    • /api/support — поддержка


4. БИЗНЕС-ПРОЦЕССЫ
--------------------------------------------------------------------------------

4.1. Регистрация и верификация клиента

  1) Гость регистрируется (email, пароль, ФИО, телефон +375).
  2) Входит в личный кабинет.
  3) Загружает документы (водительское удостоверение и сопутствующие файлы).
  4) Модератор проверяет документы и выставляет статус (одобрено / отклонено).
  5) После одобрения клиент может пользоваться услугами, требующими верификации
     (в т.ч. долгое бронирование).

4.2. Долгое бронирование

  1) Пользователь выбирает автомобиль категории long_booking или с соответствующим
     тарифом в каталоге.
  2) В личном кабинете указывает период (календарь), система рассчитывает цену.
  3) Отправляет заявку.
  4) Модератор рассматривает заявку (одобрение / отклонение / комментарий).
  5) Клиент видит статус в кабинете.

4.3. Краткосрочный каршеринг (поминутный / пакеты)

  На сайте представлены тарифы и каталог. Backend содержит сущности поездок
  (trips) и автопарка (vehicles). Полный пользовательский сценарий «найти машину
  на карте → начать поездку → завершить → оплата» реализован на уровне данных
  и API; интерфейс старта поездки для конечного пользователя — в стадии
  доработки.

4.4. Поддержка

  Пользователь создаёт тикет → модератор просматривает в своей панели →
  обработка вне или внутри системы (зависит от операционных процессов оператора).


5. БАЗА ДАННЫХ
--------------------------------------------------------------------------------

PostgreSQL с расширением PostGIS. Схема управляется Liquibase.

Основные таблицы (реализованные и используемые):
  • users, roles, users_roles — пользователи и роли
  • documents — документы клиентов и статусы модерации
  • vehicle_cards, vehicle_categories — каталог для сайта
  • vehicles — единицы автопарка
  • trips — поездки
  • long_booking_orders — заявки долгой аренды
  • news — новости
  • support_tickets — обращения в поддержку

Заложено в схеме, но без полного UI/бизнес-логики в приложении:
  • wallets, transactions — кошелёк и платежи
  • reviews — отзывы
  • damage_reports — акты повреждений
  • и другие сущности для будущего расширения (биллинг, страховые кейсы и т.д.)

Полный SQL-скрипт схемы без комментариев: docs/database-script.sql

7. ПРЕИМУЩЕСТВА И ОТЛИЧИЯ ОТ АНАЛОГОВ В БЕЛАРУСИ
--------------------------------------------------------------------------------

Рынок каршеринга в РБ historically сосредоточен в Минске (Yandex Drive, Anytime
и др.); в регионах (в т.ч. Гродно) предложение заметно уже. FredAvto позиционируется
как платформа, которую региональный оператор может развернуть и адаптировать под
локальный рынок.

7.1. Региональная и локальная ориентация

  • Язык интерфейса — русский; валюта BYN; телефоны +375
  • Контент и зоны карты ориентированы на конкретный город (Гродно)
  • В отличие от федеральных приложений с фокусом на столицу, FredAvto изначально
    проектировался под регионального оператора и «свой» автопарк

7.2. Единая платформа: маркетинг + операции

  • Публичный сайт, каталог, новости, советы, заправка — не отдельный лендинг,
    а часть одного приложения с общей авторизацией и API
  • Каталог vehicle cards отделён от fleet (vehicles): удобно вести витрину
    и реальный парк независимо (разные фото, тарифы, категории)

7.3. Долгое бронирование «из коробки»

  • Календарь, расчёт стоимости, заявки и модерация встроены в личный кабинет
  • Категория long_booking в каталоге
  • Многие классические каршеринги в РБ делают акцент на поминутку; долгая аренда
    часто уходит в отдельные прокатные сервисы — здесь оба сценария на одной платформе

7.4. Встроенная модерация документов

  • Двухэтапный процесс: загрузка клиентом → проверка модератором
  • Не нужен отдельный внешний сервис верификации на старте
  • Прозрачные статусы в личном кабинете

7.5. Гибкое администрирование для малой команды

  • Роли USER / MODERATOR / ADMIN с понятным разделением
  • Модератор закрывает типовые операции без доступа к управлению ролями
  • Панели moderator.html и admin.html без тяжёлого frontend-фреймворка —
    быстрый вход для оператора

7.6. Прозрачный каталог и тарифы

  • Категории от standard до electric, cargo, exclusive
  • На главной — диапазоны тарифов по всему каталогу; на услугах — детали по авто
  • Клиент видит структуру цен до регистрации

7.7. Карта зон и правила заправки

  • Leaflet-карта зон завершения поездки
  • Отдельная страница fueling.html с правилами для белорусского контекста
  • Снижает нагрузку на поддержку за счёт self-service информации

7.8. Самостоятельное развёртывание (self-hosted)

  • Open stack: Spring Boot + PostgreSQL + Docker
  • Оператор не привязан к чужому облаку каршеринга; данные и логика у себя
  • Удобно для учебных, пилотных и муниципальных проектов, white-label решений

7.9. Расширяемая архитектура

  • Liquibase-миграции, заложенные сущности кошелька, транзакций, отзывов
  • PostGIS для будущей привязки машин к координатам из БД
  • REST API готов к мобильному приложению или интеграции с телематикой

7.10. Сравнение с типичными альтернативами в РБ

  Классический каршеринг (Yandex Drive, Anytime и аналоги):
    + Крупный автопарк, мобильные приложения, поминутная модель в больших городах
    − Слабое присутствие в регионах; долгая аренда часто не в фокусе;
      оператор не может развернуть «свою» копию платформы

  Прокат автомobileй (Sixt, локальные прокаты):
    + Долгая аренда, офисная модель
    − Нет поминутного каршеринга, нет единого цифрового кабинета с документами
      и модерацией в одном потоке

  Такси / ride-hailing (Yandex Go и др.):
    + Подача за минуты, не нужны права на управление авто клиентом
    − Другая бизнес-модель; нет аренды «сел и поехал сам»

  FredAvto занимает нишу: региональный цифровой оператор каршеринга с каталогом,
  верификацией, долгим бронированием и возможностью автономного хостинга — то, что
  сложно получить, просто подключившись к столичному агрегатору.


8. ТЕКУЩИЙ СТАТУС РЕАЛИЗАЦИИ (ЧЕСТНАЯ ОЦЕНКА)
--------------------------------------------------------------------------------

Полностью или хорошо реализовано:
  • Регистрация, вход, сессии, роли
  • Профиль и загрузка документов
  • Модерация документов
  • Каталог vehicle cards (публичный + CRUD модератора)
  • Долгое бронирование (заявки, расчёт, модерация)
  • Новости, поддержка (создание + просмотр модератором)
  • Админ-панель пользователей и ролей
  • Публичные страницы, карта, тарифы, советы, заправка
  • Docker, миграции БД, тесты, документация

Частично реализовано:
  • Поездки: API и история в кабинете есть; UI начала/завершения поездки для USER — нет
  • Автопарк (vehicles): CRUD через API; полноценный UI управления fleet — нет
  • Зоны на карте: заданы в JavaScript, не загружаются из PostGIS/БД

Заложено в БД, но без полного функционала в приложении:
  • Кошелёк, транзакции, оплата
  • Отзывы, акты повреждений
  • Полная телематика (GPS машин в реальном времени)

11. КРАТКОЕ РЕЗЮМЕ
--------------------------------------------------------------------------------

FredAvto (shift-backend) — это комплексная веб-платформа каршеринга для белорусского
рынка: от landing и каталога автомобилей до личного кабинета, верификации документов,
долгого бронирования, новостей, поддержки и админ-панелей. Технически проект построен
на современном стеке Spring Boot + PostgreSQL/PostGIS с Docker-деплоем.

Главные конкурентные преимущества в контексте Беларуси: региональный фокус (не только
Минск), совмещение поминутного каршеринга и долгой аренды, встроенная модерация
документов, прозрачный каталог в BYN, правила для локального рынка (заправка, +375),
а также возможность автономного развёртывания оператором без зависимости от
столичных агрегаторов.

Проект находится в стадии зрелого MVP: клиентские и операционные сценарии для
каталога, кабинета и долгой аренды работоспособны; сценарии поминутных поездок
и платежей требуют следующей итерации разработки.
